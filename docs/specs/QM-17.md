# QM-17 — Consulter et gérer ses cours

Résumé du cahier de recette d'Aleksa Tovarlaza (25/11/2026). Dev back : Zeki Inceoglu.

> En tant qu'enseignant, je consulte la liste de mes cours importés et gère mes supports PDF
> (pages et quiz associés, mise à jour ou suppression d'un cours).

## Endpoints

**Attention — deux contrats différents dans l'équipe.** QM-11 (front + recette) utilise
`/api/cours`, camelCase, ids numériques. Le front QM-17 (`feature/consultation-gestion-cours`,
`src/features/courses/infrastructure/CourseDto.ts`) suppose `/api/v1/courses`, snake_case
(`version_courante`, `nb_pages`, `after_page`), ids en chaîne, et les codes `COURS_INTROUVABLE`
(404), `NON_PROPRIETAIRE` (403), `POSITION_INVALIDE` (422), `COURS_VERROUILLE` (409). Ce front
tourne uniquement en mock (pas encore d'adaptateur HTTP). **Ne rien implémenter de QM-17 avant que
l'équipe ait choisi un contrat.** Tableau ci-dessous écrit avec les chemins QM-11, à ajuster.

| Méthode | Chemin | Succès |
|---|---|---|
| GET | `/api/cours` | 200 : liste des cours **de l'enseignant connecté uniquement** : `idCours`, `titre`, `version` (active), `nbPages`, `nbQuiz` |
| GET | `/api/cours/{id}` | 200 : cours + version courante + emplacements (`[{ id, type: QUIZ\|LEADERBOARD, apresPage }]`) |
| POST | `/api/cours/{id}/versions` | 200 : nouvelle version (multipart `fichier`) + `alertes` de repositionnement |
| PUT | `/api/cours/{id}/structure` | 200 : enregistre les positions `[{ idEmplacement, apresPage }]` |
| DELETE | `/api/cours/{id}` | 204 |

Contrôles communs : pas d'auth → 401 ; cours inconnu → 404 `COURS_INTROUVABLE` ; cours d'un
autre enseignant → 403 `NON_PROPRIETAIRE` (rien n'est lu ni modifié).

## Règles métier

- **Nouvelle version** : mêmes contrôles de fichier que QM-11 (413 / 415 / 422). La version k
  est archivée (jamais supprimée), la k+1 devient courante, `idCours` ne change pas ; fichier
  `v{k+1}.pdf` à côté de `v{k}.pdf`. En cas de refus, la version courante ne change pas et aucun
  fichier n'est écrit.
- **Réapplication des emplacements** : chaque quiz/leaderboard garde son `apresPage`. Si
  `apresPage` > nouveau `nbPages`, il est rattaché à la dernière page et apparaît dans `alertes`.
- **Structure** : `apresPage` doit être dans `1..nbPages`, sinon refus (**code non défini** —
  le front attend 422 `POSITION_INVALIDE`) et rien ne change.
- **Suppression** : supprime le cours, ses versions, ses emplacements, ses résultats et le dossier
  `{STORAGE_DIR}/{idCours}/`. La confirmation est côté front.
- **Cours en séance** : mise à jour refusée pendant une présentation (le front attend 409 `COURS_VERROUILLE`). La présentation (CU2.1) n'existe pas encore → hors périmètre.

## Points ouverts (réserves de la recette — ne pas trancher seul)

1. Supprimer un cours déjà joué : purge (cette conception) ou interdit (dossier général §3.1) ?
2. Chemins `/api/cours` vs `/api/v1/courses`.
3. Codes d'erreur à l'import : 400 (cette conception) vs 415/422 (QM-11) → on suit QM-11.
4. Écran après l'import : éditeur ou menu des cours (concerne le front).
