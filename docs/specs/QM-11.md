# QM-11 — CU1.2 Importer un cours PDF

Résumé du cahier de recette d'Aleksa Tovarlaza (21/11/2026). Dev back : Zeki Inceoglu.

> En tant qu'enseignant, j'importe le support de cours au format PDF, afin de pouvoir lui associer
> des quiz et le présenter à mes étudiants.

## Endpoint

`POST /api/cours` — `multipart/form-data` : `titre` (texte), `fichier` (PDF).

Succès **201** — le front (`feature/importer-un-cours-pdf`, `coursApi.ts`) lit exactement ces trois champs :
```json
{ "idCours": 1, "idVersion": 1, "nbPages": 10 }
```
(on peut ajouter `titre`, ignoré par le front.) Les erreurs sont `{ "code", "message" }` à plat ;
le front affiche `message` tel quel, donc il doit être rédigé pour l'enseignant.
Effets : un cours (propriétaire = enseignant connecté), sa version n°1 marquée courante, avec
`nbPages` et une empreinte (SHA-256) par page ; fichier écrit en `{STORAGE_DIR}/{idCours}/v1.pdf`,
même taille que l'original.

## Contrôles, dans cet ordre

| # | Condition | Statut | code |
|---|---|---|---|
| 1 | Pas d'en-tête d'auth | 401 | `NON_AUTHENTIFIE` |
| 2 | Titre absent, vide ou fait d'espaces | 400 | `TITRE_MANQUANT` |
| 3 | Fichier > 50 Mo (limite encore « à définir », mettre en constante) | 413 | `FICHIER_TROP_VOLUMINEUX` — conseiller compression / découpage |
| 4 | Type MIME ≠ `application/pdf` **ou** les premiers octets ≠ `%PDF` | 415 | `FORMAT_NON_PDF` |
| 5 | PDF illisible (corrompu, tronqué) | 422 | `PDF_ILLISIBLE` — conseiller de réexporter depuis la source |
| 6 | PDF chiffré | 422 | `PDF_CHIFFRE` — demander un PDF non protégé |
| 7 | Stockage des données indisponible | 503 | `BDD_INDISPONIBLE` — « Réessayez dans quelques minutes ou prévenez l'administrateur » |

**Atomicité** : en cas d'erreur, rien n'est créé — ni cours, ni version, ni fichier sur le disque.
Si l'enregistrement échoue après l'écriture du fichier, le fichier est supprimé.
